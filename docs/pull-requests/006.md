## 1. The controller now has one home

`docs/replacement-controller/` moves into `controller/docs/`, beside the implementation: `DESIGN.md` (was CONTROLLER-DESIGN.md), `HARDWARE.md` (was HARDWARE-SPEC.md), `SHOPPING-LIST.md`, `STEAM-ADAPTER.md`, with the directory guide at `controller/CLAUDE.md`. Two new documents split the plan from its history:

- **`BUILD-ORDER.md`** — the sequencing spine: two tracks (bench vs installation), which purchase unlocks which phase, which measurement closes which order, and a plain answer to "why buy hardware before measuring" (Group A depends on no measurement; its only hard dependency is being in hand before the Phase 2 soak; the measurement-dependent parts are exactly what stays unordered).
- **`DECISIONS.md`** — every settled decision with its rejected alternatives and reopen conditions, so the plan documents state each decision once and stop re-litigating.

All ~530 inbound references are rewritten: the requirements register and generated checklist, Rust doc comments, fixtures, deploy.sh, and the top-level indexes. The recurring "not a fix for I1" disclaimers are deleted from the living docs and the register (OPS-09 removed); the dated history stays in INVESTIGATIONS.md and STORY-LOG.md.

## 2. The independent temperature sensor is out

The PT1000/MAX31865 subsystem is removed end to end: design and hardware sections (§ numbers kept stable; HARDWARE.md §7 carries the tombstone), shopping list (Group A: ~$233 → ~$203, and the build's only soldering goes with it), both deploy configurations, 22 requirements + checklist entries (now 114), and the full Rust implementation — HAL channel, safety events, supervisor sampling/starvation, config plumbing, e2e scenarios. Rationale in `DECISIONS.md` W3: it was never load-bearing for the safety case (the valve owns the envelope; the Therma K carries commissioning verification), and its only authority was an all-off through the same valve it was second-guessing. One revert recovers it if a Phase 3/4 measurement ever impeaches the valve's self-report.

A side effect worth noting: the daemon's production start path previously refused unconditionally because no MAX31865 driver was ever written — that refusal is gone.

## 3. The 4-channel converter question, answered and recorded

Waveshare's **USB TO 4CH RS485 (B)** cannot replace the three single-channel converters: the manufacturer's own wiki states the four RS485 channels have **no isolation between them**, so all three field grounds would share one domain — and the steam link's mandatory ground tie would join them. Recorded in D3 so it isn't re-shopped.
