## What was wrong

The safety gate rated endpoints and never looked at their arguments. That is fine for every endpoint that does one thing, and wrong for the one that does not.

`save_variable.cgi` is a single call that writes any of **105** persistent configuration variables. It was exposed as `command` at 2/5 — a rating earned by the one write this app makes, the amplifier's stored volume at index 43. The table even said so: *"Only index 43 (volume) is used by this app."*

That note described [`app/src/api/client.ts`](https://github.com/ntotten/Kohler-DTV-Plus/blob/master/app/src/api/client.ts). It did not describe the proxy, which called `checkAccess(name, 'command')`, read the request body, and passed it to `kohlerGet` verbatim. Anything that could reach the local proxy could write all 105 indices:

| Index | Variable | Consequence |
| --- | --- | --- |
| 39 | `valve_max_temp` | Raises the maximum temperature the valve will deliver |
| 41 | `valve_auto_purge` | The cold-water purge the UI reads run state from |
| 61, 62 | `six_port_calibration_valve1/2` | Factory calibration — moves real water temperature away from the setpoint |
| 86, 88 | `wifi_password`, `wifi_SSID` | Network credentials |
| 99 | `max_valve_runtime` | How long the valve may run before shutting off |

Index 39 is the one that stings. `DISCLAIMER.md` tells operators this app "clamps to that limit; it never raises it", and the UI does clamp — against `max_temp`, read live from the controller. `max_temp` **is** index 39. The clamp was applied against a number the same proxy would rewrite on request. The promise held for the app's own screens and not for the proxy underneath them, which is the part reachable from anywhere on the LAN.

Exposed since `04414ad` on 2026-07-26; five weeks. **Nothing was ever written by it** — `setVolume` is the only caller in the codebase, and it sends index 43. Found by reading the gate against the repository's own documents, not by anything going wrong.

## What changed

**A parameter allowlist in the same table as the ratings.** Every exposed endpoint now declares which parameters it accepts and what values each may take. Checked immediately after the risk check, refused with the same `403` so the two refusals look alike.

Design decisions, for the record:

- **In `cgi-safety.mjs`, not `middleware.mjs`** — the whole policy stays auditable in one place, and the startup self-check, the live self-test and `GET /api/safety` can all see it.
- **`index` is `required`** on `save_variable.cgi`. Were it optional, omitting it would hand the controller whatever it defaults to and the allowlist would never be consulted.
- **The startup self-check throws** when an exposed endpoint has no parameter policy at all, so the next generic endpoint cannot arrive the way this one did. `params: {}` is a real policy meaning "takes no parameters", not a placeholder.
- **`GET /api/safety` publishes the policy** alongside the ratings, via a `describeParams` helper — a bare `RegExp` serialises to `{}`, which would make the endpoint quietly claim a constrained parameter was unconstrained.
- **Unknown parameter *names* are refused**, which settles a question we cannot settle without hardware: the vendored docs disagree on whether `save_variable` takes `index`/`value` ([cgi-endpoints.md](https://github.com/ntotten/Kohler-DTV-Plus/blob/master/research/xagon0/docs/web-interface/cgi-endpoints.md)) or `idx`/`val` ([temperature-system.md](https://github.com/ntotten/Kohler-DTV-Plus/blob/master/research/xagon0/docs/control-logic/temperature-system.md)). Neither spelling gets through, so it does not have to be decided on a live shower.
- **Values match a strict decimal before `Number()`.** `Number("0x2b")` is 43, but the query string would carry `"0x2b"` — validating a different value from the one that gets sent.

Checking the rest of the exposed surface found no second hole, but `quick_shower.cgi`, `start_user.cgi`, `steam_on.cgi`, `rain_on.cgi`, `music_on.cgi` and `light_on.cgi` were all unconstrained too and now carry bounds read from the controller's own web UI in `research/controller-mirror/js/`. The five exposed read endpoints take no parameters and now say so.

## Notes for the reviewer

**The self-test's parameter checks are deliberately offline.** They live in the safety-policy section that already runs before anything reaches the controller. Proving the *command* path live would mean sending a command, and `npm run selftest` never does. The single live probe is a query string on `values.cgi` — a 0/5 read, so a broken gate costs one harmless fetch — which is enough to show the middleware consults the policy rather than only the module being correct.

**The temperature bound is not a scald guard, and does not pretend to be.** `26-130` admits either unit and rejects garbage; the gate cannot know the configured unit or `max_temp`, both of which live in `values.cgi`. The real clamp is `max_temp` applied in the UI — and what makes that clamp mean something now is that index 39 is no longer writable through the proxy.

**Four documents were corrected rather than one patched**, because all four made a claim about the gate that was true of the ratings and not of the arguments: `DISCLAIMER.md`, `PROTOCOL.md`, `CONTRIBUTING.md`, `AGENT.md`. `CONTRIBUTING.md` asks for a recorded reason when widening the exposed surface; it now says narrowing deserves the same note, so the next reader can tell a decision from an oversight.

**`STORY-LOG.md` carries the reversal**, including a **For Kohler** section. The substantive point for their product team: `save_variable.cgi` is an unauthenticated generic write to all 105 config variables through one endpoint, with no privilege separation between setting the amplifier volume (43) and raising the valve's maximum temperature (39) or overwriting six-port calibration (61, 62) — the same GET, one number apart. On this system `max_temp` is 113 °F, already above the 109 °F scald threshold, and index 39 can raise it further.

One thing worth saying plainly: the gate had a startup self-check, a live self-test and a unit-test file specifically guarding it. All three checked that the *ratings* held, because that was the model. A model that omits something does not fail loudly — it just never asks.
