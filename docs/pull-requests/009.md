## Findings

- **Valve 2 start-up:**
  - four `3A 01 03` address-clears, then the identification reads
  - a configuration block read, written (`8F`, block 08) and read back
  - `A9 01 07 08`, then polling at address `00`

  Valve 1's start-up has no configuration write and opens with `3A 01 01`.
- **Runtime timer:** in 22 minutes with no status polling, the only command was control `81` (mode and setpoint) at 910 s. It put the valve's countdown back to 1800, the refresh DESIGN.md expects after 900 s.
- **Setpoint field:** 90/95/96/99/100 °F read 0x0145/015E/0163/0177/0181. That isn't tenths of a °C, which #7's README had implied; the scale is left open.
- **Outlets:** valve 2's `87` command ends in one flow byte per port (`64` open, `00` closed).
- **Pause and resume:** pause is the stop. Resume is a full start, and the runtime timer restarts at 1800.
- **Fail-off:** cutting the K-99695's power stopped the water in about 2 s. Pin 5 and a driven line stayed up, so the valve closes on the silence alone.
- **Pin 5 is supplied by the valve:** it read 12.82 V with the controller unpowered and its cable pulled out (correction in #10).
- **Re-addressing:** valve 2's move to address `13` happens again, and a restart puts it back at `00`. Why is still open.
- **Empty outlet string:** for the other valve it keeps that valve's armed selection, for either valve. A valve-1-only start ran valve 2 once it had an outlet armed, and not straight after a restart. This settles #7's "last selection or default".
