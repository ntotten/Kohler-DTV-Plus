Sets up [oxfmt](https://github.com/oxc-project/oxc) as the repo-wide formatter and applies it.

Rebased onto `main` after the replacement-controller docs landed, so this is now five commits: tooling, the sweep, the convention docs, one rendering fix the sweep exposed, and the newly-arrived `STEAM-ADAPTER.md`.

## Why

There was no formatter and no root `package.json`. Markdown tables were hand-aligned and had drifted out of true, quote style varied between files, and several files were missing a final newline. oxfmt covers everything here in one binary — Markdown, TypeScript, CSS, YAML, HTML, JSON — in about 300 ms for the whole tree.

```bash
npm install && npm run format   # or npm run format:check
```

## Config choices

All made to match what is already in the repo rather than to impose a new style. See [`.oxfmtrc.json`](.oxfmtrc.json), where the reasoning is recorded inline.

- **`proseWrap: "preserve"`** — paragraphs are never reflowed. Headings, list markers, tables, and code fences still get normalised. Reflowing would have rewritten nearly every doc and buried real edits in whitespace churn.
- **`singleQuote` scoped to JS/TS/CSS** via an override. The code and the app's CSS already use single quotes (the CSS runs 10 single to 4 double); YAML and HTML already use double, so they keep the default.
- **`printWidth: 100`**, matching the existing code.

## What is deliberately not formatted

- `research/xagon0/` — vendored third-party material. Reformatting it would break the byte-for-byte correspondence [PROVENANCE.md](research/xagon0/PROVENANCE.md) claims.
- `research/diagnostics/`, `research/controller-mirror/`, `app/test/fixtures/` — raw captures. These are cited as what the hardware actually returned, and `values-live.json` plus the two app fixtures are single-line dumps straight off the controller. They stay exactly as captured.

This is a project rule rather than a formatter preference, so it is now written into AGENT.md and CONTRIBUTING.md as well as the config.

## One real bug the sweep exposed

`docs/repair/extraction-plan.md` described the S19 image as "MQX 3.8 kernel + RTCS + filesystem drivers + all Kohler application code". The line wrapped so that the last `+` landed at column 0 — and CommonMark reads `+ ` at column 0 as a bullet, so **GitHub has been rendering half that sentence as a one-item list all along**.

The formatter made the mis-parse permanent (rewrote `+` to `-`, indented the continuation lines), which is what made it visible. Commit 876870e rewraps so the `+` sits at the end of the previous line. Same words, now rendering as the paragraph it was written as.

Separately, `viewer/README.md` had an ordered list numbered 1, 2, 3, 3, 4 — oxfmt corrected it to 1–5, which is what GitHub was already displaying.
